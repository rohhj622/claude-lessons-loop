# 스키마 — 노트를 쓸 때 지킬 것

이 파일이 쓰기 게이트다. 노트를 만들거나 고치기 전에 여기를 읽는다.
`lessons-writer` 서브에이전트와 `/wrap` 스킬 둘 다 이 파일을 정본으로 삼는다.

---

## 0. 파일 만들기 전에 확인할 것

1. **같은 ID 가 이미 있는지 폴더 전역에서 확인한다.** ID 는 전역에서 고유해야 한다.
   하위 폴더 단위로 채번하면 조용히 충돌한다.
2. 노트 참조는 반드시 `[[노트명]]` 링크로 쓴다. 텍스트로만 이름을 쓰지 않는다.
3. 프론트매터를 먼저 채우고 본문을 쓴다. 빈 값(`""`, `[]`)은 없는 것과 같다 —
   `lint.py` 가 둘을 같이 잡는다.
4. **자격증명·키 값·내부 주소는 어떤 노트에도 쓰지 않는다.** 환경변수 이름까지만 남긴다.

---

## 1. lesson (LSN) — 이 플러그인이 실제로 쓰는 타입

파일: `Lessons/LSN-YYYY-MM-DD-NNN.md`
`NNN` 은 그날의 일련번호다 (`001` 부터).

### 프론트매터

```yaml
---
type: lesson
id: LSN-2026-08-05-001
aliases: ["안 불리는 규범은 조용히 낡는다"]
name: "안 불리는 규범은 조용히 낡는다"
impact: high          # high | medium | low — 세션 시작 훅이 이 값으로 거른다
date: 2026-08-05
tags: [lesson, 검증]
author: "[[Claude]]"  # 사람이 직접 쓴 것이면 자기 이름
---
```

`impact` 가 없으면 세션 시작 훅의 대상에서 조용히 빠진다. **반드시 넣는다.**

### 본문 — 절 이름과 순서를 고정한다

```markdown
## 상황
무엇을 하던 중이었는지. 한두 줄.

## 실수 내용
정확히 무엇을 틀렸는지. 관찰된 사실만.

## 원인
왜 그렇게 됐는지. 추측이면 추측이라고 적는다.

## 앞으로 할 것 · 하지 말 것
다음에 같은 상황에서 무엇을 확인할지. 실행 가능한 문장으로.
```

### 같은 실수가 다시 나오면

**새 노트를 만들지 않는다.** 기존 노트에 절을 덧붙인다.

```markdown
## 재현
- 2026-09-02: 같은 원인, 다른 경로. (한 줄 요약)
```

원본은 지우지 않는다 — 조건과 재현 경로가 각각 다르다.

## 2. Lessons/INDEX.md — 훅이 기계로 읽는 표

칸 이름은 `ID · 제목 · 중요도 · 날짜` 넷이다. 순서는 상관없다.

```markdown
## 검증·판단 방법론

| ID | 제목 | 중요도 | 날짜 |
|---|---|---|---|
| [LSN-2026-08-05-001](LSN-2026-08-05-001.md) | 안 불리는 규범은 조용히 낡는다 | high | 2026-08-05 |
```

- 묶음 제목은 마크다운 2단(`## `)이다. 세션 시작 훅이 이 제목으로 절을 찾는다.
  대상 묶음 이름은 **플러그인 설정**의 `상시 주입 묶음 이름` 에 있다.
- **칸 순서는 바꿔도 된다.** 머리글의 이름으로 찾는다. 다만 이름 넷은 그대로
  둔다. 이름을 바꾸면 교훈이 안 붙고, 그때는 왜 못 읽었는지가 세션 시작에 나온다.

## 3. project (PRJ) — 함께 쓰는 경우에만

이 플러그인은 교훈만으로도 돈다. 프로젝트 노트까지 같이 쓸 때만 아래를 지킨다.
`lint.py` 가 검사하는 대상이 이 타입이다.

파일: `Projects/<프로젝트명>/_PRJ-YYYY-NNN.md`

### 프론트매터 필수 필드 13개

`type` `project_type` `id` `aliases` `name` `status` `priority` `program`
`owner` `team` `start_date` `updated` `tags`

`end_date` 는 제외한다 — 진행 중이면 비는 것이 정상이다.

`program` 은 닫힌 어휘다. 허용 값은 `_Meta/lint.config.json` 의 `programs` 에 있다.
`상위:하위` 표기를 쓰면 `:` 앞부분만 검사한다. 값을 둘 이상 주면 여러 갈래에
걸친 과제라는 뜻이다.

> **어휘를 늘릴 때는 이 문서와 `lint.config.json` 을 같이 고친다.**
> 한쪽만 고치면 검사기와 문서가 갈리고, 그 상태로도 각자 일관돼서 아무도 못 알아챈다.

### `## 현재 상태` 블록

진행상황의 정본이다. 사람이 30초 안에 읽을 수 있어야 한다.

- 필수 키 넷: `요약:` `최근:` `다음:` `막힘:`
- 본문 **12줄 이하**, 불릿 **1단**, 볼드 **6쌍 이하**
- 프론트매터 `updated` 와 본문의 `<!-- 최종 갱신: YYYY-MM-DD -->` 가 같아야 한다

> 상한이 없던 동안 한 노트가 60줄·볼드 46쌍·불릿 3단까지 자라 사람이 못 읽는
> 상태가 됐다. 임계값은 규정을 지키던 노트 15건의 실측 분포 상단이다.

**세션 서술을 여기 쌓지 않는다.** 성격에 따라 셋으로 가른다 — 세션 서술은
커밋 메시지로, 영구 사실은 그 노트의 기존 상설 절로, 남은 일은 이슈 노트로.

### 골격 절 이름

`lint.py` 가 통일을 요구하는 것들이다.

| 쓰면 안 되는 이름 | 정본 |
|---|---|
| 목적 | 개요 |
| 이슈 | 이슈 목록 |
| 자료원 (Sources) | 자료원 |
| 산출 대상 (Targets) · 산출물 (Targets) | 산출물 |

## 4. 검사기 두 개

```bash
python _Meta/lint.py --selftest   # 검사기 자신이 살아 있는지 먼저
python _Meta/lint.py              # 마지막 줄을 그대로 보고한다
python _Meta/drift.py             # 끊긴 링크·없는 경로·손으로 쓴 총계·중복 ID
```

`lint.py` 의 교훈 검사는 `_Meta/index_md.py` 를 쓴다. 표를 읽는 코드는 그 한 벌뿐이다.
그 파일이 없으면 **검사를 약하게 하지 않고 도구 실패로 보고한다.**

둘 다 **읽기 전용이다. 파일을 고치지 않는다.**

둘 다 **대상 0건을 "전부 통과"가 아니라 도구 실패로 보고한다.** 깨끗해서 0인지
못 찾아서 0인지 구분이 안 되면 그 0은 근거가 아니기 때문이다.
`drift.py` 는 PyYAML 이 필요하다.
