# /wrap — 세션 마무리

기록 폴더는 환경변수 `LESSONS_VAULT` 가 가리키는 곳이다. 이 아래에 `Lessons/` 가 있다.

## 목표

세션이 닫히면 사라질 맥락을 파일로 옮긴다. 배운 것은 `Lessons/` 아래 LSN 노트로
쌓이고, 그것이 다음 세션에서 훅을 통해 자동으로 돌아온다.

세션 서사의 정본은 **커밋 메시지**다. 그 커밋의 diff 가 곧 증거라서, "했다고 적었지만
안 한 일"이 남을 수 없다. 별도의 일지 노트를 만들지 않는다.

## 방법

1. **이번 세션에서 실제로 한 일을 대화 기록 기준으로 정리한다.**
   계획했지만 안 한 일과 반드시 갈라 적는다. 이 구분이 없으면 하려던 것이
   한 것으로 기록된다.

2. **교훈 후보를 고른다.** 후보가 되는 것은 이번 세션에서 실제로 틀린 것,
   전제가 뒤집힌 것, 재현 조건이 분명한 함정이다. 잘 된 일은 교훈이 아니다.

3. **교훈 후보는 파일을 만들기 전에 사용자에게 제목과 한 줄 요약으로 확인받는다.**
   이 단계를 빼면 겪지도 않은 일이 교훈으로 적힌다. 승인한 것만 노트가 된다.

4. **승인된 것만 `Lessons/LSN-YYYY-MM-DD-NNN.md` 로 쓴다.**
   형식은 `_Meta/스키마.md` 의 lesson 절을 따른다. 프론트매터에 `impact`
   (high / medium / low) 를 반드시 넣는다 — 세션 시작 훅이 이 값으로 거른다.

   **같은 실수가 다시 나오면 새 노트를 만들지 않는다.** 기존 노트에 `## 재현` 절을
   날짜와 함께 덧붙인다. 조건과 경로가 다르면 원본을 지우지 않는다.

5. **`Lessons/INDEX.md` 표에 한 줄을 더한다.** 칸 이름은 ID · 제목 · 중요도 ·
   날짜 넷이다. 훅이 머리글 이름으로 칸을 찾으므로 순서는 상관없지만, 이름을
   바꾸면 교훈이 안 붙는다.

   **행을 안 더하면 그 교훈은 회수돼도 제목 없이 나온다.** `_Meta/lint.py` 가
   이걸 잡는다.

   ```
   | [LSN-2026-08-05-001](LSN-2026-08-05-001.md) | 안 불리는 규범은 조용히 낡는다 | high | 2026-08-05 |
   ```

   행은 주제별 묶음(`## ` 2단 제목) 아래에 넣는다. 세션 시작 훅이 대상으로 삼는
   묶음 이름은 **플러그인 설정**의 `상시 주입 묶음 이름` 에 있다.

6. **형식 검사를 돌린다.**

   ```bash
   python "$LESSONS_VAULT/_Meta/lint.py" --selftest
   python "$LESSONS_VAULT/_Meta/lint.py"
   ```

   `--selftest` 를 먼저 돌린다. 빈 결과가 "전건 통과"인지 "검사기 고장"인지는
   이걸로만 갈린다. 교훈만 쓰는 볼트에서도 정상으로 끝나고, 그때는
   `교훈 N/N OK · PRJ 노트 없음(검사 대상 아님)` 이 나온다.

   교훈 검사는 셋을 본다. `impact` 가 있고 어휘 안에 드는지, `id` 가 파일명과
   같은지, `Lessons/INDEX.md` 에 그 행이 있는지다. 셋 다 없으면 회수가 조용히
   빠지거나 제목 없이 나오는 자리다.

   `OK` 가 아니면 위반 항목을 그 자리에서 고치고, 고치지 않고 넘어갈 거면 그
   이유를 사용자에게 한 줄로 보고한다. 조용히 넘기지 않는다.

7. **qmd 를 쓰고 있으면 색인을 갱신한다.** 안 하면 방금 쓴 교훈은 의미검색에
   안 잡힌다. qmd 가 없으면 이 단계는 건너뛴다 — 기본 검색기는 파일을 그때그때
   읽으므로 색인이 없다.

   ```bash
   qmd update && qmd embed
   ```

   합쳐서 20초 안팎이다. 끝나면 `qmd collection list` 의 `lessons` 파일 수가
   실제 LSN 개수 + 1(INDEX.md) 과 맞는지 확인한다.

   > 이 갱신이 닷새 밀려 LSN 25건(당시 29%)이 검색에서 통째로 빠진 적이 있다.
   > 그 결과 이미 있는 교훈을 모른 채 반대 내용의 교훈을 새로 쓰는 일이 벌어졌다.
   > SessionEnd 훅이 같은 일을 자동으로 하지만, 그건 이중 방어이지 대체가 아니다.

8. **변경한 파일 목록과 각 한 줄 요약을 사용자에게 보고한다.**

9. **커밋 안 된 변경이 있으면 사용자에게 커밋 여부를 묻는다.** 동의하면 커밋한다.
   거절하면 그대로 둔다. 커밋 메시지에 담을 것:

   - 제목: `<주제> — <한 줄 결과>`
   - 왜 했는지 (배경·계기)
   - **실제로** 한 일 — 계획했지만 안 한 일과 구분해서
   - 발견한 것 / 뒤집힌 전제
   - **미완·미검증 항목을 정직하게**
   - 관련 LSN ID

   > 변경이 없는 세션은 기록도 남지 않는다. 억지로 만들지 않는다.

## 승격

같은 원인으로 묶이는 노트가 3건 넘게 쌓이면, 그것을 상시 규칙 문서(`CLAUDE.md`)의
한 줄로 올린다. 이 판단은 사람이 한다.

올려도 원본 LSN 은 지우지 않는다 — 조건과 재현 경로가 각각 다르다.

## 제약

- 대화에서 확인되지 않은 성과를 기록하지 않는다. 테스트 실패·미완료는 그대로 적는다.
- 이미 기록이나 git 히스토리에 있는 내용을 중복 기록하지 않는다.
  세션에만 있는 맥락(왜 그렇게 결정했는지, 뭐가 막혔는지)을 우선한다.
