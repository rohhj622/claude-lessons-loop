# /claude-lessons-loop:configure — 설정과 점검

이 스킬은 **상태를 먼저 보고하고, 빠진 것마다 사용자에게 물어서 채운다.**
승인 없이 파일을 만들거나 고치지 않는다. 이미 있는 것은 덮지 않는다.

**사용자 기계를 바꾸는 일은 대신 하지 않는다.** 전역 npm 설치와 모델 내려받기는
명령과 용량을 알려 주고 사용자가 직접 돌리게 한다.

---

## 1. 상태를 먼저 찍는다

```bash
sh "${CLAUDE_PLUGIN_ROOT}/hooks/py.sh" doctor.py
```

**판정을 직접 하지 말 것.** 경로가 있는지 없는지를 눈으로 다시 확인하지 말고
이 출력을 그대로 사용자에게 보여 준다. 판정은 `hooks/doctor.py` 한 곳에만 있다.
두 곳에서 판정하면 반드시 갈라진다.

출력이 아예 안 나오면 그것은 "정상"이 아니라 점검기가 못 돈 것이다.
파이썬이 있는지부터 확인하고 사용자에게 그렇게 보고한다.

`MISSING` 인 줄만 아래에서 하나씩 처리한다. 전부 `OK` 면 3번으로 건너뛴다.

---

## 2. 빠진 것을 채운다

### 기록 폴더가 MISSING 일 때

값을 둘 자리가 셋이고, 위가 이긴다.

1. **환경변수 `LESSONS_VAULT`** — 어디서든 이긴다. 임시로 써 보거나 CI 에서 쓴다.
2. **플러그인 설정** — Claude Code 는 플러그인을 켤 때 물어본다. 나중에 바꾸려면
   `/plugin` 에서 이 플러그인의 설정을 연다. **Codex 에는 이 자리가 없다.**
3. **설정 파일** — 점검기가 찍는 `설정 파일` 줄의 경로다. 양쪽에서 다 읽힌다.

어느 쪽에 넣을지 사용자에게 묻는다. 설정 파일을 고르면 그 경로에 쓴다.
**이미 있는 파일이면 읽어서 필요한 키만 바꾼다. 통째로 덮지 않는다** —
다른 값이 같이 들어 있을 수 있다.

```json
{ "vault_dir": "<경로>" }
```

경로를 정했는데 폴더가 없으면 만들지 물어본다. 승인하면:

```bash
mkdir -p "<경로>/Lessons"
```

### 교훈 목록이 MISSING 일 때

`Lessons/INDEX.md` 가 없다는 뜻이다. 템플릿을 복사할지 물어본다.

```bash
cp -R "${CLAUDE_PLUGIN_ROOT}/templates/vault/." "<경로>/"
```

템플릿에는 `_Meta/index_md.py` 가 같이 들어 있다. **이 파일이 없으면 `lint.py` 가
교훈 검사를 아예 못 한다** — 표를 읽는 코드가 거기 한 벌뿐이라 없으면 약한 검사로
대체하지 않고 도구 실패로 보고한다. 볼트를 이미 쓰고 있는 사람이 이 파일만 없다면
그것만 복사할지 물어본다.

**복사 전에 반드시 `ls` 로 대상 폴더를 확인한다.** 파일이 이미 있으면 복사하지
않는다. 사용자가 쌓아 둔 기록을 예시 파일로 덮는 사고가 이 스킬에서 일어날 수
있는 가장 나쁜 일이다. 겹치는 파일이 있으면 이름을 대며 사용자 판단을 구한다.

### 상시 주입 묶음 이름을 정할 때

설정의 `상시 주입 묶음 이름` 은 `INDEX.md` 의 `## ` 제목과 **완전히 같아야 한다.**
앞부분만 맞는 것으로는 안 걸린다. 실제로 제목이
`## 검증·판단 방법론 (도메인 무관 — 항상 훑을 것)` 인 볼트에서 기본값
`검증·판단 방법론` 을 그대로 두어 상시 교훈이 0건이 된 일이 있다.

그러므로 값을 묻기 전에 **있는 묶음을 먼저 읽어 후보로 보여준다.**

```bash
grep '^## ' "<볼트>/Lessons/INDEX.md"
```

나온 제목에서 `## ` 만 떼고 나머지를 그대로 쓴다. 괄호 안 설명도 지우지 않는다.
사용자가 고른 것을 설정에 넣고, 넣은 뒤 `session-start.py` 를 한 번 돌려
교훈이 실제로 나오는지 건수로 확인한다. 0건이면 성공이 아니다.

### qmd 가 MISSING 일 때

**대신 설치하지 않는다.** 이렇게만 말한다.

> qmd 는 없어도 된다. 없으면 기본 검색기로 돈다.
> 의미검색을 쓰고 싶으면 직접 이걸 돌린다.
>
> ```
> npm i -g @tobilu/qmd
> ```
>
> 첫 색인에서 모델 셋(합계 2 GB 안팎)을 내려받는다. 전부 이 PC 에서 돌고
> 그 뒤로는 검색에 API 호출이 없다. **검색이 로컬이라는 뜻이지 이 도구 사용
> 전체가 로컬이라는 뜻은 아니다.** 모델 호출 자체는 밖으로 나간다.

설치했다고 하면 1번을 다시 돌려 확인한다. 말만 듣고 됐다고 적지 않는다.

### 검색 색인이 MISSING 일 때

컬렉션부터 확인한다.

```bash
qmd collection list
```

`lessons` 가 없으면 만들지 물어본다. **설정 파일을 손으로 쓰지 않는다** —
사용자가 다른 프로젝트 컬렉션을 이미 넣어 뒀을 수 있고, 그 파일을 덮으면
그쪽 색인이 통째로 무효가 된다. qmd 에게 시킨다.

```bash
qmd collection add "<경로>/Lessons" --name lessons
```

이름은 반드시 `lessons` 다. 훅이 `-c lessons` 로 이 이름을 부른다.

그다음 색인은 사용자가 돌리게 한다. 시간이 걸리고 모델을 내려받는다.

```
qmd update && qmd embed
```

## 3. CLAUDE.md 절 (선택)

`${CLAUDE_PLUGIN_ROOT}/templates/CLAUDE.md` 를 읽고 **절 제목만** 목록으로
보여 준다. 각 절이 무엇을 막으려는 것인지 한 줄씩 붙인다.

어느 절을 가져갈지 사용자가 고르게 한다. 고른 것만 **이 제품의 상시 지침 파일**
끝에 덧붙일지 다시 확인받는다. 파일 자리는 제품마다 다르다.

- Claude Code — `~/.claude/CLAUDE.md`
- Codex — `~/.codex/AGENTS.md`
- 그 밖 — 사용자에게 어디에 두는지 묻는다. 짐작해서 쓰지 않는다.

**승인 없이 그 파일에 쓰지 않는다.** 매 세션 통째로 컨텍스트에 들어가는 사용자
소유 파일이고, 길이가 곧 비용이다.

권하는 것과 권하지 않는 것을 갈라 말한다.

- **"검증 습관"** — 가져갈 만하다. 다만 자기 경험으로 얻은 것만 남기라고
  말한다. 안 겪은 일을 규칙으로 두면 그 규칙부터 썩는다.
- **"여기 적을 것과 적지 말 것"** — 가져갈 만하다.
- **"기록"** — 안 가져가도 된다. 세션 시작 훅이 같은 일을 한다.
- **"하지 않을 것"** — 예시다. 운영 DB 얘기는 교훈 회수와 무관하다.
  자기 상황에 맞는 것이 아니면 넣지 않는다.

---

## 4. 끝에 다음 한 걸음을 말한다

상태에 따라 딱 하나만 말한다.

- 기록 폴더가 아직 없다 → 플러그인 설정에서 경로를 넣으라고.
- 폴더는 됐고 교훈이 없다 → 세션을 마칠 때 `/claude-lessons-loop:wrap` 을
  돌리면 첫 교훈이 생긴다고.
- 교훈은 있는데 색인이 없다 → `qmd update && qmd embed` 를 한 번 돌리라고.
- 전부 됐다 → 새 세션을 열면 상시 교훈이 붙는다고. **지금 세션에는 안 붙는다**,
  세션 시작 훅은 이미 지나갔다.

---

## 제약

- 이 스킬은 **읽고, 묻고, 승인받은 것만 쓴다.** 조용히 고치는 일이 없다.
- 이미 있는 파일을 덮지 않는다. 겹치면 멈추고 사용자에게 넘긴다.
- 전역 설치와 모델 내려받기는 사용자가 돌린다.
- 사용자가 "됐다"고 말한 것을 근거로 적지 않는다. 1번을 다시 돌려 확인한다.
